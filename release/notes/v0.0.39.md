Interrupted-deploy cleanup at exit, Logs → Crash screen

- A graceful exit mid-deploy (q/Esc/Ctrl+C, SIGINT/SIGTERM/SIGHUP, shutdown/reboot) now stops the pipeline in-process and removes the half-built service immediately — unit, env file, project tree and journal entry — instead of deferring the cleanup to the next launch
- Scripted `__deploy` handles the same signals (quiesce + removal, exit 130); the `__cleanup` background sweep additionally stops orphaned `ghost-*` transient build/probe units before removing their trees
- A journaled deploy holds an exclusive flock (`deploy.lock`) until its entry is cleared, so background cleanup can never race a live deploy, even across SIGKILL/shutdown
- A unit left `failed` by an interrupted deploy is recovered (reset-failed + re-enable) when started from the Services screen; selftest exercises the leftover sweep against live systemd
- New Logs → Crash tab: persistent crash.log history of interrupted/recovered deploys (reload on entry, `d` clears, size-capped)
