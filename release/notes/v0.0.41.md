# v0.0.41 — stops the panel from dropping junk dirs into your cwd

One fix since v0.0.40, and it is the bug that made `0/` and `ignore/` appear
in whatever directory the panel was started from (reported as `~/0` and
`~/ignore`).

## Fixes landing since v0.0.40

- **hoster(sandbox): precreate only path-valued cache env keys**
  - `precreate_cache_dirs` ran `create_dir_all` over *every* `cache_env()`
    value. Two of them are scalar settings, not paths:
    `pnpm_config_pm_on_fail=ignore` and `pnpm_config_minimum_release_age=0`.
    Resolved against the process cwd, each precreate pass therefore created
    an empty `ignore/` and an empty `0/` next to wherever the panel had been
    launched — e.g. straight into `$HOME`.
  - The precreate pass now goes through an explicit `PATH_ENV_KEYS`
    allowlist, and any *relative* path value is resolved against the project
    directory, never the process cwd. Scalar settings are never mkdir'd.
  - Covered by `precreate_creates_only_project_paths_never_cwd_rel_paths`,
    which asserts every path key resolves absolutely under the project and
    that both scalar pnpm settings yield `None`.

## Reproducibility

- Single musl build path, byte-identical between `scripts/release-local.sh`
  and `.github/workflows/release.yml` (same pinned-by-digest Arch container,
  pinned rustc 1.98.0, `--locked`). Compare `SHA256SUMS` across the two.
