# v0.0.40 — deploy-anomaly fix, released properly

Downstream of the v0.0.39 curate (which carried the pre-fix build), this
release is the same panel code with the two landing fixes folded in and
byte-verifiable end-to-end:

## Fixes landing since v0.0.39

- **deploy(engine): finish the deploy worker before reconciling at exit**
  - An interrupted deploy (q / Esc / Ctrl+C, SIGINT/SIGTERM/SIGHUP,
    shutdown/reboot) used to race its own cleanup: exit-notices were printed
    through an fd2 that `StderrCapture` still held, so they leaked into
    `deploy.log` as a duplicated cleanup pairтного container, and the worker
    could die before writing its `done:` line.
  - Now the exit path joins the deploy worker first (`wait_deploy_worker`),
    captures the in-flight URL before reconciling, resolves the state of the
    capture (`stderr_capture_active`), and prints exactly one terminal marker
    `== deploy … done: interrupted ==`. Verified end-to-end (fresh build +
    installed musl binary): one cleanup pair, one `crash.log` line, empty
    journal.
- **ci: fix clippy failures under the pinned MSRV 1.88** (no runtime change,
  but CI lint must stay green to publish).

## Reproducibility

- Single musl build path, byte-identical between `scripts/release-local.sh`
  and `.github/workflows/release.yml` (same pinned-by-digest Arch container,
  pinned rustc, `--locked`). Compare `SHA256SUMS` across the two.

## Verified

- E2E deploy-interrupt on the installed binary: clean single cleanup pair,
  `done: interrupted`, one `crash.log` entry, `{}` journal.
- Clippy `-D warnings` lint-test green on both CI providers (GitHub, Codeberg).
