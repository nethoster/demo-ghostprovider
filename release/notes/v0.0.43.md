# v0.0.43 — honest deploys: live port verify, fresh paraglide pins

Three fixes since v0.0.42, all found live on a user machine:

## Changes landing since v0.0.42

- **fix(netstatus): drop dead branches, make emission observable**
  - Removed the `is_empty()` check after `HashSet::insert` (never true)
    and the `fresh_host && len == 1` disjunct (covered by `first`).
  - The emission decision is now the pure, unit-tested
    `should_emit(first, due)`; `note_down() -> bool` lets tests count
    emitted lines without capturing stderr (the old `lines`/`written`
    shim was never wired).
- **fix(pins): bump paraglide plugin hashes after upstream drift**
  - `cdn.jsdelivr.net` serves new bytes under the same `@4`/`@2` major
    tags (message-format 4.5.0, m-function-matcher 2.3.0); the
    fail-closed seed correctly refused them with `sha256 mismatch`.
  - New pins verified against unpkg plus npm registry timestamps
    before re-pinning.
- **fix(deploy): purge stale unit drop-ins, verify live port before ok**
  - `create_unit`/`remove_unit` now delete leftover
    `<service>.service.d/` — a stale `SEARXNG_SETTINGS_PATH` override
    crash-looped searxng while the deploy printed `done: ok`.
  - Success is now gated on `wait_until_port_open()`: `is-active` alone
    could catch a `Restart=always` unit inside a brief active window
    between restarts. `done: ok` / `listening on` only print when the
    port really accepts connections.

## Reproducibility

- Single musl build path, byte-identical between `scripts/release-local.sh`
  and `.github/workflows/release.yml` (same pinned-by-digest Arch container,
  pinned rustc 1.98.0, `--locked`). Compare `SHA256SUMS` across the two.

- Full `cargo test` green (169 + 2 passed, 0 failed).
- Release signature checked in CI against `docs/release.pub`
