# v0.0.42 — [r] now restarts the selected service

One change since v0.0.41: the services screen's `[r]` key stops being a
passive refresh and becomes the recovery action users already assumed it
was.

## Changes landing since v0.0.41

- **tui(services): make [r] restart the selected service**
  - `[r]` used to only re-read `state.json` and re-run
    `systemctl --user is-active`, so a dead unit stayed dead — pressing
    `[r]` expecting the service to come back did nothing.
  - `[r]` now runs `systemctl --user restart` on the selected row and then
    re-reads the rows, so the status column reflects the restart.
    `restart` also starts a stopped/failed unit and clears its failed
    state, making the key an up-recovery action, not just a bounce.
  - With an empty list `[r]` keeps the old refresh semantics (there is
    nothing to restart). No confirmation — same weight as
    `[s]top`/`star[t]`. Hint line updated to `[r]estart`.

## Reproducibility

- Single musl build path, byte-identical between `scripts/release-local.sh`
  and `.github/workflows/release.yml` (same pinned-by-digest Arch container,
  pinned rustc 1.98.0, `--locked`). Compare `SHA256SUMS` across the two.
